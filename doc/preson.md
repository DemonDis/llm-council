# Профиль сотрудника для планирования работы с ИИ

Ниже приведён формат профиля в Markdown, который можно использовать как отдельный файл на каждого сотрудника. Его сможет анализировать ИИ для:

- оценки соответствия сотрудника задаче или предложению;
- распределения задач;
- определения необходимого уровня контроля;
- формирования команды;
- планирования загрузки;
- выявления рисков;
- составления плана развития;
- подготовки вопросов сотруднику или заказчику;
- оценки, какую задачу лучше дать специалисту сейчас, а какую — позже.

Рекомендуемый принцип: **описывать не “характер человека”, а его рабочее поведение, наблюдаемые навыки, предпочтения и ограничения**.

---

# 1. Основные правила профилирования

## Что важно фиксировать

1. **Технические навыки**
   - технологии;
   - инструменты;
   - бизнес-компетенции;
   - уровень самостоятельности;
   - наличие практического опыта.

2. **Мягкие навыки**
   - коммуникация;
   - ответственность;
   - работа с неопределённостью;
   - способность планировать;
   - умение давать и принимать обратную связь;
   - переговоры;
   - презентации;
   - командная работа.

3. **Рабочий психологический профиль**
   - предпочтительный стиль работы;
   - отношение к неопределённости;
   - потребность в структуре;
   - удобный формат коммуникации;
   - реакция на срочность;
   - предпочтительный тип обратной связи;
   - мотивационные факторы.

4. **Ограничения**
   - доступные часы;
   - часовой пояс;
   - текущая загрузка;
   - нежелательные типы задач;
   - ограничения по командировкам, звонкам или публичным выступлениям.

5. **Предпочтения**
   - самостоятельная работа или парная;
   - технические или управленческие задачи;
   - исследование или реализация;
   - стабильные процессы или динамичные проекты.

6. **Доказательства**
   - на основании чего выставлена оценка;
   - когда она проверялась;
   - насколько оценка достоверна.

---

# 2. Универсальная шкала hard skills

Для технических и профессиональных навыков рекомендуется использовать шкалу от 0 до 5.

| Оценка | Значение |
|---|---|
| 0 | Нет опыта |
| 1 | Знаком с основами, может выполнять простые действия по инструкции |
| 2 | Может решать типовые задачи с регулярной помощью |
| 3 | Уверенно выполняет типовые задачи самостоятельно |
| 4 | Решает сложные задачи, выбирает подходы, помогает другим |
| 5 | Экспертный уровень, проектирует решения, обучает и принимает архитектурные решения |

Желательно дополнительно указывать:

- годы практического опыта;
- уровень самостоятельности;
- дату последнего применения навыка;
- наличие подтверждённого результата;
- интерес к развитию навыка.

---

# 3. Универсальная шкала soft skills

| Оценка | Значение |
|---|---|
| 1 | Навык практически не проявляется или требует постоянной поддержки |
| 2 | Проявляется в простых и знакомых ситуациях |
| 3 | Стабильно проявляется в обычной рабочей обстановке |
| 4 | Сотрудник хорошо использует навык в сложных ситуациях |
| 5 | Сотрудник является сильной стороной команды в этом навыке и может обучать других |

Soft skill лучше описывать не только цифрой, но и через наблюдаемое поведение.

Например:

```text
Коммуникация: 4/5
Проявление: ясно формулирует статус, заранее сообщает о рисках, умеет адаптировать объяснение под собеседника.
Ограничение: иногда перегружает сообщение техническими деталями.
```

```md
## 5. Рабочий психологический профиль

### Предпочтительный уровень структуры

Умеренно высокий.

Анна хорошо работает с чётко сформулированными задачами, критериями готовности и ожидаемым результатом. Может самостоятельно декомпозировать задачу среднего размера. Для полностью неопределённых задач ей полезно сначала вместе сформулировать цель и ограничения.

### Отношение к неопределённости

Среднее.

Готова проводить техническое исследование, если понятно, какой вопрос необходимо решить. Неэффективна в задачах без ожидаемого результата и при частом изменении направления.

### Предпочтительный темп работы

Стабильный плановый темп с короткими итерациями.

Лучше работает, когда может выделить несколько часов на непрерывную концентрацию. Частые переключения между задачами снижают продуктивность.

### Предпочтительный формат коммуникации

- письменное описание задачи;
- короткие технические обсуждения;
- комментарии в системе управления задачами;
- демонстрация готового результата.

Не рекомендуется без необходимости включать в большое количество встреч.

### Предпочтительный формат обратной связи

- конкретная;
- индивидуальная;
- с объяснением причины замечания;
- привязанная к результату или коду.

### Реакция на изменения приоритетов

При единичном изменении приоритета адаптируется нормально. При постоянных изменениях без объяснения может снизиться скорость работы. Желательно объяснять причину смены приоритета и фиксировать новый порядок задач письменно.

### Реакция на стресс и срочность

Может работать со срочной задачей, если определены:

- причина срочности;
- ожидаемый результат;
- срок;
- критерии приемки;
- какие текущие задачи временно приостанавливаются.

При одновременной выдаче нескольких срочных задач требуется помощь руководителя в расстановке приоритетов.

### Рабочая мотивация

Анну мотивируют:

- технически содержательные задачи;
- возможность самостоятельно выбирать способ реализации;
- понятный результат;
- улучшение качества продукта;
- развитие backend-компетенций;
- работа в команде с сильными специалистами.

### Демотивирующие факторы

- микроменеджмент;
- большое количество встреч;
- незафиксированные требования;
- постоянные переключения;
- публичная критика;
- задачи без понятного критерия готовности.
```

# 9. Как собирать команду

При подборе команды важно искать не просто сотрудников с максимальными оценками, а сочетание компетенций.

## Роли в команде

Для каждой задачи ИИ может определить:

- владельца результата;
- технического исполнителя;
- аналитика;
- QA или специалиста по контролю качества;
- эксперта по предметной области;
- специалиста по коммуникации с клиентом;
- наставника;
- резервного специалиста.

## Правила формирования команды

### 1. Один владелец результата

У каждой задачи должен быть один ответственный. Остальные участники помогают ему, но не заменяют ответственность.

### 2. Не дублировать одинаковые слабости

Если два специалиста плохо работают с неопределённостью, команда может долго не переходить к реализации. Желательно добавить человека, который умеет структурировать неизвестные требования.

### 3. Закрывать критические навыки

Для каждого обязательного навыка должно быть:

- минимум одно лицо с уровнем 4–5;
- желательно второе лицо с уровнем 3+;
- понятный резерв на случай отсутствия специалиста.

### 4. Учитывать коммуникационную нагрузку

Сильный технический специалист не всегда должен общаться с заказчиком. Иногда эффективнее разделить роли:

- один человек работает с клиентом;
- другой выполняет техническую реализацию.

### 5. Не перегружать сильных специалистов

Высокий навык не означает свободную ёмкость. ИИ должен учитывать текущую загрузку и стоимость переключения между проектами.

### 6. Выделять развивающие задачи отдельно

Развивающую задачу не следует маскировать под обычную задачу с критичным сроком. Нужно явно указывать:

- кто учится;
- кто отвечает за результат;
- кто проверяет работу;
- какой допустимый уровень ошибок.

# 13. Важное поле: уверенность в оценке

Одной цифры недостаточно. Например, оценка Python `4` может быть получена из:

- самооценки сотрудника;
- результата реального проекта;
- тестового задания;
- мнения руководителя;
- устаревших данных.

Поэтому для каждого навыка желательно хранить:

```md
- Оценка: 4/5
- Уверенность: высокая
- Источник: результаты двух проектов и code review
- Дата проверки: 2026-07-15
```

Это позволит ИИ отличать подтверждённую компетенцию от предположения.

```md
2. Учитывать текущую загрузку и доступную ёмкость.
3. Учитывать рабочие предпочтения, формат коммуникации и переносимость неопределённости.
4. Не делать медицинских, психиатрических или дискриминационных выводов.
5. Не использовать личные чувствительные данные, если они не связаны напрямую с рабочей задачей.
6. Опирайся только на наблюдаемые рабочие факты и заявленные предпочтения.
7. Отделяй подтверждённые данные от предположений.
8. Для каждого решения указывай причины, риски и уровень уверенности.
9. Не назначай сотруднику задачу только потому, что у него высокий технический навык: проверяй загрузку, коммуникационные требования и цену ошибки.
10. Если информации недостаточно, сначала сформируй список уточняющих вопросов.

Для каждой задачи анализируй:

- техническое соответствие;
- soft skills;
- стиль работы;
- уровень самостоятельности;
- доступность;
- мотивационный интерес;
- риски;
- необходимость наставника;
- необходимость резервного специалиста;
- потенциал развития.

Всегда возвращай результат в структуре:

1. Краткий вывод.
2. Рекомендуемый сотрудник или команда.
3. Обоснование.
4. Оценка соответствия.
5. Риски.
6. Недостающие данные.
7. План работы.
8. Формат постановки задачи.
9. Контрольные точки.
10. Альтернативные варианты.
```

# 15. Что не следует включать в профиль

Не рекомендуется хранить и использовать для рабочих решений:

- медицинские диагнозы;
- сведения о здоровье без прямой рабочей необходимости;
- политические и религиозные взгляды;
- национальность и расу;
- сексуальную ориентацию;
- семейное положение;
- личные конфликты, не связанные с работой;
- предположения о психических расстройствах;
- субъективные ярлыки вроде «ленивый», «токсичный», «трудный человек».

Вместо этого следует писать:

```text
Плохо:
"Сотрудник ленивый и неорганизованный."

Хорошо:
"В задачах без промежуточных сроков может откладывать начало работы. Лучше работает при наличии контрольной точки и явно зафиксированного результата."
```

```text
Плохо:
"Сотрудник конфликтный."

Хорошо:
"В спорных технических обсуждениях может занимать жёсткую позицию. Эффективнее обсуждает разногласия при наличии заранее определённых критериев выбора."
```

# 16. Минимальная версия профиля

Если не хочется создавать большой документ, можно начать с такой компактной версии:

```md
# Профиль: [Имя]

## Роль

[Должность и уровень]

## Hard skills

| Навык | Уровень 0–5 | Доказательства |
|---|---:|---|
| [Навык] | [оценка] | [проект/результат] |

## Soft skills

| Навык | Уровень 1–5 | Наблюдаемое поведение |
|---|---:|---|
| Коммуникация | [оценка] | [описание] |
| Ответственность | [оценка] | [описание] |
| Планирование | [оценка] | [описание] |
| Работа с неопределённостью | [оценка] | [описание] |

## Сильные стороны

- [пункт]
- [пункт]

## Слабые стороны и ограничения

- [пункт]
- [пункт]

## Предпочтительный стиль работы

- [описание]

## Подходящие задачи

- [задача]
- [задача]

## Нежелательные задачи

- [задача]
- [задача]

## Рабочая мотивация

- [фактор]

## Нужный уровень контроля

[низкий / средний / высокий]

## Доступность

- Ёмкость: [часов в неделю]
- Текущая загрузка: [часов]
- Свободно: [часов]

## Рекомендации ИИ

[Как лучше ставить задачи этому сотруднику]
```

Такой формат уже будет достаточен для первичного распределения задач, но для качественного планирования команды лучше использовать полный профиль с указанием доказательств, ограничений, мотивации и рабочего стиля.
